# Компактные представления графов

## Мотивация

Веб-графы, социальные сети и RDF-хранилища оперируют графами с **миллиардами рёбер**: веб-граф из снимка домена легко достигает `10^9` узлов и `10^10`–`10^11` дуг. Хранить такой граф наивно — например, списком смежности или в формате CSR (compressed sparse row) — означает тратить `O((n + m) log n)` бит: на каждое из `m` рёбер уходит `log2 n` бит на хранение идентификатора соседа [[11](#ref-navarro)]. Для `n = 10^9` это около 30 бит на ребро только под ссылки, и весь граф перестаёт помещаться в оперативную память.

**Компактные структуры данных** ставят другую цель: хранить граф у **информационно-теоретической нижней границы** (или с небольшим множителем от неё), сохраняя при этом быструю навигацию — перечисление соседей, проверку смежности и вычисление степени за `O(1)`–`O(log n)`. Метрикой служат **биты на ребро** (bits/edge, bits/link).

Важно сразу очертить рамки темы. Эта страница — про **представление графа в памяти и его объём**, а не про алгоритмы обхода. Здесь нет BFS, DFS или Дейкстры; вместо этого мы разбираем, как закодировать структуру смежности компактно и при этом дёшево по ней навигировать. Алгоритмы на графах работают поверх любого такого представления.

Связь с базами данных и распределёнными системами прямая (подробнее — в разделе [Применения](#применения-в-бд-и-распределённых-системах)): графовые СУБД, RDF-триплсторы и in-memory аналитика над веб- и социальными подграфами выигрывают именно от того, что компактное представление позволяет держать больший граф целиком в оперативной памяти.

## Информационно-теоретическая граница

Сколько бит **в принципе** нужно, чтобы закодировать ориентированный граф на `n` узлах с `m` рёбрами (петли допускаются)? Каждое ребро — это упорядоченная пара `(u, v)`, то есть один из `n^2` возможных элементов матрицы смежности. Число различных таких графов равно числу способов выбрать `m` ячеек из `n^2`:

```
число графов = C(n^2, m)
```

Отсюда нижняя граница на размер любого представления:

```
LB = log2 C(n^2, m)  бит
```

При `m << n^2` эту величину удобно оценить так (биномиальная форма раскрывается через формулу Стирлинга):

```
log2 C(n^2, m) ≈ m · log2(n^2 / m)  бит
```

Главная метрика страницы — **биты на ребро** `LB / m ≈ log2(n^2 / m)`.

**Числовой пример (проверено).** Для `n = 10^5`, `m = 10^6`:

```
n^2 = 10^10,  n^2 / m = 10^4
log2(10^4) ≈ 13.29 бит/ребро
```

Аппроксимация `m · log2(n^2/m)` даёт `≈ 13.29 · 10^6` бит; точное `log2 C(10^10, 10^6) ≈ 14.73 · 10^6` бит (`≈ 14.73` бит/ребро). Аппроксимация занижает точное значение, потому что отбрасывает положительный член порядка `m · log2 e` — поэтому это именно нижняя оценка ведущего порядка, а не точное равенство.

По отношению к этой границе Наварро [[11](#ref-navarro)] вводит **трихотомию** представлений:

| Класс | Размер | Смысл |
|---|---|---|
| Неявное (implicit) | `LB + O(1)` бит | по сути оптимально, без явных указателей |
| Сукцинктное (succinct) | `(1 + o(1)) · LB` бит | граница плюс асимптотически пренебрежимая добавка |
| Компактное (compact) | `O(LB)` бит | в константу раз больше границы |

Реальные веб-графы сжимаются **сильно ниже** наивной оценки `log2(n^2/m)`, потому что они не случайны: у них есть локальность (соседи имеют близкие идентификаторы) и подобие (у соседних страниц похожие списки ссылок). Именно эту избыточность эксплуатируют практические методы ниже.

## Базовый инструментарий: bit-vectors с rank/select

Почти все компактные представления графов строятся над **битовыми векторами** с двумя запросами. Пусть `B[0..n-1]` — битовый вектор:

- **`rank_1(i)`** — число единиц в `B[0..i]` (сколько установленных бит до позиции `i` включительно);
- **`select_1(j)`** — позиция `j`-й единицы в `B`.

Ключевой результат Джекобсона [[1](#ref-jacobson)]: к битовому вектору можно добавить **`o(n)` дополнительных бит** так, чтобы `rank` выполнялся за `O(1)`. Кларк [[2](#ref-clark)] показал аналогичное для `select` — `O(1)` с `o(n)` дополнительной памятью.

Если сам вектор разрежен или сжимаем, применяют **сжатые битовые векторы RRR** (Raman, Raman, Rao) [[3](#ref-rrr)]: они хранят `B` в `nH_0(B) + o(n)` бит (где `H_0` — энтропия нулевого порядка распределения бит) и при этом поддерживают `rank`/`select` за `O(1)`.

Эта связка «битовый вектор + rank/select» — фундамент для всего, что описано ниже: сукцинктных деревьев, `k^2`-деревьев и компактных списков смежности.

## Сукцинктные деревья (LOUDS, BP, DFUDS)

Дерево с `n` узлами требует по информационной границе около `2n` бит (число различных упорядоченных деревьев — число Каталана, `log2 C_n ≈ 2n`). Существует три классических сукцинктных кодирования, все укладываются в `2n + o(n)` бит и навигируют через `rank`/`select`.

- **LOUDS** (Level-Order Unary Degree Sequence, Джекобсон [[1](#ref-jacobson)]). Узлы обходятся по уровням; степень каждого узла записывается **унарно**: `d` единиц и завершающий ноль. Навигация (первый ребёнок, следующий брат, родитель) сводится к `rank`/`select` над этой последовательностью.
- **BP** (Balanced Parentheses, Munro–Raman [[4](#ref-munro-raman)]). Обход в глубину: при входе в узел пишется `(`, при выходе — `)`. Сбалансированная скобочная последовательность из `2n` символов кодирует дерево и поддерживает запросы «размер поддерева» и «предок».
- **DFUDS** (Depth-First Unary Degree Sequence). Обход в глубину, степень узла пишется унарно скобками; позволяет переходить к `i`-му ребёнку за `O(1)`.

Полная функциональность над BP (все навигационные операции за `O(1)`) достигается структурой **range min-max tree** Наварро и Садаканэ [[5](#ref-navarro-sadakane)].

| Представление | Размер | Поддерживаемые операции |
|---|---|---|
| LOUDS | `2n + o(n)` бит | первый ребёнок, следующий брат, родитель, степень |
| BP | `2n + o(n)` бит | размер поддерева, предок, навигация (с range min-max) |
| DFUDS | `2n + o(n)` бит | `i`-й ребёнок за `O(1)`, степень, навигация |

## Компактные графы

Дерево — частный случай графа. Для произвольных графов используется несколько семейств представлений.

### (a) Общие графы через bitmaps + rank/select

Простейшее компактное представление: записать матрицу смежности по строкам как **конкатенацию битовых строк** и навесить `rank`/`select`. Тогда:

- перечисление соседей узла `u` — это `select_1` по подряд идущим единицам в его строке;
- проверка смежности `u → v` — чтение одного бита;
- степень `u` — разность `rank_1` на границах строки.

Для разреженных графов плотный битмап неэффективен, поэтому хранят сжатый (RRR) либо переходят к специализированным схемам ниже.

### (b) k²-деревья

`k^2`-дерево (Brisaboa, Ladra, Navarro) [[6](#ref-k2tree-2009)] [[7](#ref-k2tree-2014)] — это **квадродерево над матрицей смежности**. Матрица `n × n` делится на `k^2` равных подматриц (при `k = 2` — на 4 квадранта). Для каждого квадранта хранится один бит: `1`, если в нём есть хотя бы одно ребро, и `0`, если он целиком нулевой. Нулевые квадранты **обрезаются** (не разворачиваются дальше), ненулевые рекурсивно делятся тем же способом до отдельных ячеек.

Дерево хранится двумя битовыми векторами: `T` — биты всех внутренних уровней, `L` — биты листового уровня; навигация и перечисление соседей идут через `rank` над `T`. Конструкция эксплуатирует **разреженность и кластеризацию** рёбер и, в отличие от методов, ориентированных на прямых соседей, симметрично поддерживает как **прямых, так и обратных** соседей (преемников и предшественников).

На веб-графах `k^2`-дерево достигает **3.3–5.3 бит на ребро** (Information Systems, 2014, т. 39, с. 152–174) [[7](#ref-k2tree-2014)]. Подробный разбор кодирования — в разделе [Пример](#пример-k²-дерево).

### (c) WebGraph (Boldi & Vigna)

Фреймворк **WebGraph** (Boldi, Vigna) [[8](#ref-webgraph)] сжимает список смежности, эксплуатируя два свойства реальных веб-графов:

- **локальность** — соседи страницы имеют близкие идентификаторы (если упорядочить URL лексикографически), поэтому разности соседних идентификаторов малы и кодируются **gap-кодированием**;
- **подобие** — у близких страниц похожие списки ссылок, поэтому список соседей кодируется как **ссылка на список-образец** плюс битовая маска копирования (copy-list) и поправки.

Дополнительно применяются **интервальное кодирование** подряд идущих соседей и **ζ-коды** (zeta codes) — семейство универсальных кодов целых, настроенное под степенное распределение разностей. На корпусе WebBase WebGraph достигает **≈ 3.08 бит на ребро**, а на транспонированном графе **≈ 2.89 бит на ребро** (WWW 2004) [[8](#ref-webgraph)].

### (d) Re-Pair над списками смежности

Клод и Наварро [[10](#ref-claude-navarro-repair)] применяют **грамматическое сжатие Re-Pair** к конкатенированным спискам смежности: алгоритм многократно заменяет самую частую пару символов новым нетерминалом, строя грамматику, порождающую исходную последовательность. Повторяющиеся фрагменты списков соседей (то самое подобие) свёртываются в правила грамматики. Метод даёт компактное представление с прямым доступом к соседям и конкурентен с WebGraph по объёму при быстрой навигации.

### (e) Планарные и сепараторные кодирования

Для **планарных** графов (и графов с малыми сепараторами) существуют сукцинктные кодирования, использующие теорему о сепараторах: граф разбивается на части малыми сепараторами, что позволяет закодировать его близко к информационной границе для соответствующего класса. Подробности — в соответствующей главе учебника Наварро [[11](#ref-navarro)].

## RDF / помеченные графы

RDF-данные — это набор триплетов `(субъект, предикат, объект)`, то есть **помеченный граф**, где метка ребра — предикат. Альварес-Гарсия, Брисабоа и соавторы [[9](#ref-k2triples)] предлагают **k²-triples**: вертикальное разбиение по предикатам, при котором для каждого предиката строится своё `k^2`-дерево над матрицей «субъект × объект». Это даёт компактный RDF-триплстор с эффективными запросами по шаблонам триплетов (в том числе с переменными в любой позиции) — прямое приложение компактных графов к базам данных.

## Поддерживаемые запросы и их стоимость

Разные представления по-разному поддерживают четыре базовых запроса. Здесь `d` — степень обрабатываемого узла; для `k^2`-дерева `n` — число узлов.

| Запрос | CSR (списки) | bitmap + rank/select | k²-дерево | WebGraph |
|---|---|---|---|---|
| Перечисление соседей | `O(d)` | `O(d)` | `O(d · log_k n)` | `O(d)` |
| Проверка смежности `u→v` | `O(d)` или `O(log d)`* | `O(1)` | `O(log_k n)` | `O(d)` |
| Исходящая степень | `O(1)` | `O(1)` (rank) | `O(d · log_k n)` | `O(d)` |
| Входящая степень | `O(n + m)`** | через обратный битмап | симметрично прямой | требует транспонированного графа |

\* при отсортированном списке соседей проверка смежности — `O(log d)`.
\*\* в обычном CSR входящая степень требует прохода по всему графу либо отдельной транспонированной копии.

Принципиальное различие: **WebGraph ориентирован на прямых соседей** — для обратных соседей нужна отдельная транспонированная копия графа. **`k^2`-дерево** даёт прямых и обратных соседей **симметрично** из одной структуры, что ценно для RDF и двунаправленных обходов.

## Пример: k²-дерево

Возьмём ориентированный граф на `n = 4` узлах с рёбрами `0→1`, `2→3`, `3→2`. Матрица смежности `A` (строка — источник, столбец — приёмник):

```
      c0 c1 c2 c3
 r0 [  0  1  0  0 ]
 r1 [  0  0  0  0 ]
 r2 [  0  0  0  1 ]
 r3 [  0  0  1  0 ]
```

Берём `k = 2`. Матрица `4 × 4` делится на `2 × 2` сетку квадрантов `2 × 2`. Обход квадрантов — построчный: `(0,0), (0,1), (1,0), (1,1)`, где `(I, J)` покрывает строки `2I..2I+1` и столбцы `2J..2J+1`.

**Уровень 1 (вектор `T`).** Для каждого квадранта пишем бит «есть ли в нём единица»:

- квадрант `(0,0)` — ячейки `r0c0, r0c1, r1c0, r1c1 = 0,1,0,0` → есть единица → **1**;
- квадрант `(0,1)` — ячейки `r0c2, r0c3, r1c2, r1c3 = 0,0,0,0` → пусто → **0** (обрезается);
- квадрант `(1,0)` — ячейки `r2c0, r2c1, r3c0, r3c1 = 0,0,0,0` → пусто → **0** (обрезается);
- квадрант `(1,1)` — ячейки `r2c2, r2c3, r3c2, r3c3 = 0,1,1,0` → есть единица → **1**.

```
T = 1001
```

**Уровень 2 (вектор `L`).** Разворачиваем только ненулевые квадранты (в том же порядке), записывая их `2 × 2` ячейки построчно:

- квадрант `(0,0)`: `r0c0, r0c1, r1c0, r1c1 = 0,1,0,0` → `0100`;
- квадрант `(1,1)`: `r2c2, r2c3, r3c2, r3c3 = 0,1,1,0` → `0110`.

```
L = 0100 0110
```

Итоговое кодирование: `T = 1001`, `L = 01000110`. Два нулевых квадранта обрезаны, поэтому из 16 ячеек матрицы развёрнуто только 8 листовых бит. Проверка по матрице вручную совпадает: единицы в `L` стоят ровно на позициях рёбер `0→1` (в первом блоке) и `2→3`, `3→2` (во втором блоке). Это точная арифметика кодирования, а не бенчмарк.

Навигация: чтобы найти соседей узла `2`, спускаемся по `T`/`L` в поддеревья, отвечающие строке `2`; нулевые квадранты пропускаются без обращения к памяти, а позиции единиц дают столбцы-приёмники через `rank` над `T`.

## Применения в БД и распределённых системах

- **Графовые СУБД.** Компактное хранение топологии позволяет держать граф в RAM целиком, ускоряя обходы и запросы соседей без обращения к диску.
- **RDF-триплсторы.** `k^2`-triples [[9](#ref-k2triples)] сжимают триплеты и одновременно индексируют их, давая эффективные запросы по шаблонам без отдельного дискового индекса.
- **In-memory аналитика над веб- и социальными подграфами.** PageRank, поиск сообществ и подсчёт треугольников работают быстрее, когда весь подграф помещается в память; WebGraph и `k^2`-деревья делают это возможным для графов на миллиарды рёбер.
- **Хранение социальных сетей.** Списки друзей/подписок обладают подобием и локальностью, поэтому методы WebGraph и Re-Pair применимы к социальным графам так же, как к веб-графам.

Общий выигрыш один: меньше **бит на ребро** — значит, больший граф помещается в оперативную память, что радикально меняет производительность по сравнению с хранением на диске.

## Визуализация

График сравнивает расход **бит на ребро** для нескольких представлений. Подписи указывают источник каждого числа.

- **Наивный список смежности** — иллюстративная модель `≈ log2 n` бит на ребро (для `n = 10^6`, `log2 10^6 ≈ 19.9`): на каждое ребро тратится один идентификатор соседа. Это **иллюстративная модель, а не измеренный бенчмарк** — реальный расход зависит от кодирования идентификаторов.
- **k²-дерево** — `3.3–5.3` бит/ребро, измеренный диапазон на веб-графах (Information Systems, 2014) [[7](#ref-k2tree-2014)]; на графике показано среднее значение диапазона `≈ 4.3`.
- **WebGraph** — `≈ 3.08` бит/ребро на WebBase, измеренное значение (WWW 2004) [[8](#ref-webgraph)].
- **Информационно-теоретическая граница** — `≈ 13.29` бит/ребро для конкретных `n = 10^5, m = 10^6` (см. [раздел про границу](#информационно-теоретическая-граница)); это вычисленная величина для указанных параметров, а не измерение.

Столбцы `k^2`-дерева и WebGraph — реальные измеренные цифры из статей, поэтому они не несут дисклеймера; дисклеймер «иллюстративно» относится только к наивной модели и к зависящей от `n, m` границе.

## Сложность

Сводная таблица: пространство (бит) и время основных запросов. `n` — число узлов, `m` — число рёбер, `d` — степень узла; `LB = log2 C(n^2, m)`.

| Представление | Пространство (бит) | Перечисление соседей | Смежность `u→v` | Обратные соседи |
|---|---|---|---|---|
| CSR / список смежности | `O((n + m) log n)` | `O(d)` | `O(log d)`* | требует транспонирования |
| bitmap + rank/select | `O(n^2)` (плотно) / `nH_0 + o(n)` (RRR) | `O(d)` | `O(1)` | через обратный битмап |
| LOUDS/BP/DFUDS (деревья) | `2n + o(n)` | `O(d)` | — | — |
| k²-дерево | `O(m · log_k(n^2/m))`, на практике `3.3–5.3` бит/ребро [[7](#ref-k2tree-2014)] | `O(d · log_k n)` | `O(log_k n)` | симметрично прямым |
| WebGraph | `≈ 3.08` бит/ребро [[8](#ref-webgraph)] | `O(d)` | `O(d)` | требует транспонированного графа |

\* при отсортированном списке соседей.

Сукцинктные и компактные представления приближаются к границе `LB` по памяти (трихотомия из раздела [Информационно-теоретическая граница](#информационно-теоретическая-граница)), сохраняя навигацию за полилогарифмическое или линейное по степени время.
